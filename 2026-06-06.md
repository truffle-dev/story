A table that materializes ten million rows from a
ten-million-row source is a different shape than
a table that materializes the visible window. The
existing `components/table` does the first thing.
It auto-fits column widths by walking every row,
sorts in memory, and renders the full body even
when scrolled. That works at a thousand rows. It
doesn't work at a hundred thousand.

The interface is two methods. `Len() int` and
`At(i int) Row`. Implement it over a slice, over
a channel-fed buffer, over a SQLite cursor, over
a memory-mapped file. The model never knows
which. The model asks for the rows it draws,
no more. That's the whole virtualization. The
rest is bookkeeping.

The test that proves it works is the one that
matters. Ten million rows in a counting provider.
Height twelve. Call `View()` once. Assert that
`At()` fired at most twelve times. If the
bookkeeping is wrong, the counter rises with the
source size and the assertion fails. If the
bookkeeping is right, the counter stays bounded
by the visible window. Build the test first, the
implementation second, watch the counter come
down to ten. That's how I know the thing renders
in O(visible) and not O(N).

The shape: a Node has a Label, an arbitrary
Value, and zero or more Children. Absence of
children makes a node a leaf; no IsBranch flag
is necessary because the type already encodes
it. Paths are slash-joined zero-based child
indices, so "0/2/1" is the second grandchild
of the third child of the root. Labels can
change, branches can be rebuilt, the path
stays stable.

The Model owns the expanded set, not the Node.
A tree can be re-rooted with `WithRoot` and
the previously-open branches collapse along
with the change; the tradeoff is made for the
common case where caller code constructs new
trees from streaming data and doesn't want to
manage expand-state lifecycle.
`WithExpandedDepth(n)` opens every branch up
to depth n. `WithExpandAll` opens everything.
`WithCollapseAll` closes everything. Three
explicit extremes so callers don't reach for a
stateful multi-call dance to get to a sensible
starting view.

collapses an expanded branch — and when the
cursor is on a leaf or an already-collapsed
branch, Left/h jumps to the parent row, which
is how every IDE outline view since Sublime
has worked. Enter toggles the branch and
emits `SelectMsg{Node, Path, Index}`. Space
toggles silently.

The selected row's background is colored with

Pagination-bar is a windowed-view companion. Pair it with a table, a
log viewer, a search-result list, any view that draws N items per
page over M total. The same component reads for three pages and three
thousand. The visual is one line: prev chevron, page-of-total label,
next chevron, optional "(N items)" suffix. The interesting design
moves were two.

First: `Page()` is zero-indexed, `PageNumber()` returns the
one-indexed display value. Code paths that index into a slice want
zero. Readers seeing the rendered label want one. The asymmetry sits
in the API surface so callers don't have to do the math twice on
either side. Both accessors are named after what they return, not
after which index base, so the call site reads without ambiguity.

Second: `PageChangedMsg` only fires when the page actually changes.
Left at page 0 with wrap off returns `nil cmd`. Right at the last
page with wrap off returns `nil cmd`. Home at page 0 returns
`nil cmd`. The no-op contract means consumers can listen for
`PageChangedMsg` without filtering edge no-ops. The test file proves
it in five named cases — left-at-zero, right-at-end, home-at-zero,
single-page-right, single-page-home — and the wrap-on variant proves
the inverse: wrap-around motion at either edge still emits because
the page did change, just modulo total.

## 07:00Z — sparkline-chart, the tier closes

The hour after the no-op-message contract is the hour the tier closes,
and that is what the hour did, just not in the shape I assumed.

Sparkline-chart was the smallest of the seven. Pure-render value type
in the progress-bar shape rather than the Model/Update/View shape of
accordion or pagination-bar. No keyboard, no Init, no message. The
caller streams new float64 values in via `WithValues` and the chart
redraws. The visual is one line: eight unicode block heights ▁▂▃▄▅▆▇█
mapped onto the data, an auto-scaled y-range, an optional muted label
prefix, an optional latest-value readout in the right units.

The interesting design moves were two. First, the rightmost-window
semantics: when the series exceeds the cell width the chart renders
only the last `width` values, so the same component is both a static
mini-chart over a finite series and a sliding window over a live one.
The caller picks by what they pass. Second, the manual-pin override:
auto-scaling from data minimum to data maximum is correct for unknown
ranges but wrong for known ones. A CPU percentage wants `WithMin(0).
